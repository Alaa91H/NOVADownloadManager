# Batch Link Intake Review

**Date:** 2026-08-27
**Scope:** Review of batch-link collection and confirmation patterns for a bounded NOVA improvement following v2.4.35-alpha.

| ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| [JDownloader LinkGrabber](https://support.jdownloader.org/en/knowledgebase/article/linkgrabber-how-to-add-links) | Separates collection from confirmation: links can be added by clipboard, paste, a manual dialog, or the browser add-on. ## NOVA baseline

`BatchImportPage` already supports clipboard paste, one URL per line, capped range expansion (`MAX_EXPANDED_URLS = 10,000`), protocol filtering, and exact **intra-batch** deduplication. It does not expose a pre-import summary of accepted candidates, invalid protocol entries, duplicated input entries, or URLs already represented by queued/active/completed tasks. The page also has several English hard-coded labels despite existing translated batch-import keys.

## Decision and bounded acceptance criteria

The review supports an explicit, reliable transition from link collection to queueing. In NOVA, the high-confidence gap was not URL parsing: the existing batch page already caps expansion, filters capabilities, and removes exact repeats from the input. It was the submission lifecycle: a user could click the import button repeatedly while the asynchronous batch request was still pending, and the page navigated to Downloads before the store could determine whether the daemon had accepted any task.

The selected improvement preserves exact URL semantics and does not inspect, canonicalize, display, or mutate signed URL paths, query strings, fragments, credentials, or case. It adds an in-flight guard and accessible busy state to the import action, awaits the batch result, returns attempted/accepted counts from the task-store operation, and changes page only when at least one task is accepted. It retains the direct-engine capability gate, intra-batch deduplication, and intentional re-download behaviour. The page now reuses the existing translated batch placeholder rather than introducing new English-only UI strings.

A proposed pre-import count summary was deliberately excluded from this release after the controlled translation update returned empty responses across three independent attempts. No partially localised keys or fallback-only strings were committed; the feature scope was reduced to the independently verifiable submission-lifecycle fix.
